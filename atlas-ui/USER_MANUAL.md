## 0. 它到底是什么

一个跑在你电脑上的**彩票历史数据可视化 + 统计学习 demo**。

```
六合宝典 (数据源)
    │  每天 cron 自动抓
    ▼
liuhe-atlas/  (Python 后端, 数据库 + 模型)
    │  导出 snapshot.json
    ▼
liuhe-atlas-ui/  (这个 Vite/React 前端)
    │  实时计算
    ▼
你的浏览器 (localhost:5173)
```

不连外网时只跑前端没意义 — 数据全靠 cron 喂。

## 3. 选号原理 (核心问题)

页面里 5 个地方会"选号"，但**算法不一样**。搞混了会以为"数字都一样"。

### 3.1 Controls 面板里的 Top-N / Cover-N (基础模式)

代码: `src/lib/predictor.ts:167` `selectBalls()`

- **Top-N**: 取**模型预测概率最高**的 N 个球
- **Cover-N**: 取**模型预测概率最低**的 N 个球 (反向)
- 模型 = Bayesian L2, 下面 §3.3 详述

滑块范围 1-45 (49-4，留 4 个"未选")。

### 3.2 AutoPick 的 4 个模式 (高级)

代码: `src/components/AutoPick.tsx`

| 模式 | 算法 | 选出的特征 |
|------|------|------------|
| **融合** (combine, 默认) | `0.6 × 模型分 + 0.4 × 频率分`，归一化后取前 N | 模型 + 频率交集区 |
| **交集** (intersection) | 同时在模型 Top-N **和** 频率 Top-N 的球 | 两边都认可 |
| **模型** (model) | 模型 Top-N (Bayesian L2) | 跟 §3.1 一致 |
| **频率** (frequency) | 历史出现次数最多的 N 个球 | 纯 raw count |

⚠️ **当前数据只有 19 期 / 133 球**, 每球被抽 2-3 次。
四个模式的 Top-20 球**高度重叠** (因为 ±1 次的差异在统计上毫无意义)。
**要让数字不一样**:
- 把 N 调小 (N=1 一定不一样)
- 切到 **Cover-N 模式** (选的是另一端)
- 等数据涨到 50+ 期 (大约还需要 6 周)

### 3.3 Bayesian L2 模型到底怎么算 (代码细节)

代码: `src/lib/predictor.ts:81` `predict()`

**Level 1 — 单球计数**:
```
P(ball) = (count(ball) + α) / (total + 49 × α)
α = 1.0  (Laplace smoothing)
```
α>0 是为了让 0 次的球也有非零概率，避免 log(0)。

**Level 2 — 符号聚合** (年支/五行/波色):
对每个球，先算它**所属生肖 / 五行 / 波色**的概率：
```
P(zodiac(z))   = count(zodiac) / total    (对 12 生肖)
P(wuxing(wx))  = count(wuxing) / total    (对 5 五行)
P(wave(wv))    = count(wave) / total      (对 3 波色)
```
然后球的得分 = 三个符号概率的平均，再归一化。

**混合**:
```
P_blend(ball) = 0.5 × P_lvl1 + 0.5 × P_lvl2
```

**输出**: 49 个球的概率分布，按 P_blend 排序。Top-N = 排在前面的。

### 3.4 信号强度 (KL 散度)

代码: `predictor.ts:131-149`

```
KL = Σ P_blend(ball) × log(P_blend(ball) / P_uniform)
P_uniform = 1/49 = 0.02041
```

| KL 范围 | 信号解读 |
|---------|----------|
| < 0.005 | 无信号 (no-signal) — 几乎均匀 |
| 0.005-0.02 | 弱 (weak) |
| 0.02-0.05 | 中 (moderate) — 当前 0.0268 |
| > 0.05 | 强 (strong) |

KL=0.0268 的意思是：模型比"瞎选"稍微多解释了一点信息，但**远不够用来下注**。

## 4. 期望亏损模拟器 — 最重要的一块

代码: `src/components/ExpectedLossCard.tsx`

默认输入: 派彩 45×, 每年 156 期, 10 年。

数学 (代码里就是这套公式):
```
总投注   = 期数 × 年数 × 1 (每期 1 元)
期望回报 = 总投注 × 派彩 × (7 / 49)    ← 7 球中任意 1 球中奖
期望盈亏 = 期望回报 - 总投注
ROI      = 期望盈亏 / 总投注
```

⚠️ **关键认知**:
- 派彩 ≥ 49/7 ≈ 7× 时，**纯随机选号**就已经正期望
- 派彩 45× < 7×, 长期**数学上负期望**
- 你看到默认 ROI +1736.7% 是因为设的派彩是 45 (远高于真实私彩)
- **结论写在卡片底下**: "真实私彩几乎不可能达到派彩 45"

这块组件是反讽设计 — 让"看起来很赚"的数字自带 disclaimer。

## 5. Win Probability — 两条概率公式

代码: `src/components/WinProbabilityCard.tsx`

- **至少中 1 球**: `1 - C(49-7, 7) / C(49, 7) = 1 - C(42, 7)/C(49, 7)`
- **中特码 (第 7 球)**: `N / 49` (选 N 个号码时)

⚠️ **铁律**: 真实单期单注中奖概率 ≤ 1/49 = 2.04%，
**与 N 无关** (因为每球独立采样，选越多反而稀释)。
卡片底下的红字就是这行。

## 8. FAQ

### Q: 为什么 4 个 AutoPick 模式选出来数字几乎一样？
A: 数据太少 (19 期)。差异在统计噪声内。要变 → 调小 N / 切 Cover-N。

### Q: KL=0.0268 算好吗？
A: 不好不坏。"中" 等于"能看出点东西但远不够"。

### Q: 我能用这个真买彩票吗？
A: 不行。长期 ROI 必为负，模型输出不影响这一事实。
参见顶部 DisclaimerBanner + ExpectedLossCard + WinProbability 底部红字。

### Q: 想让模型更准？
A: 多抓数据，等信号自己浮出来。这个项目是**统计学习 demo**，不是产品。

### Q: snapshot.json 是怎么生成的？
A: 查 `~/dev/liuhe-atlas/logs/cron-pipeline.log` 看 cron 跑的过程，
    或 `export_snapshot.py` 看导出代码。

### Q: 没有 git 仓库？
A: 是的，两个 repo 都还没 `git init`。建议下个 milestone 加。
